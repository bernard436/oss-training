Create or update?

Two prototypes, one product: update v1, port the best screens of the Planner

v1 (Exercise 3) · the backbone

  • Server-side orchestrator, 12 tests green
  • Least-privilege permissions, audit trail, kill switch
  • Model gateway with redaction; event reader that only proposes
  • Planning mailbox with "read with the model" and "confirm and repair"
  • Shaped for production: Node server, EU endpoint, runbook

Lyon Planner · the screens to borrow

  • Gantt with override and a reason
  • Feedback: five whys → a rule, a data fix, or not a rule
  • Eval: weights, targets, guardrails, snapshots
  • Ontology view, data sources toggle
  • But: engine runs in the browser, permissions in client code

Advice: do not start a third app. Keep v1 as the product, because what the client and Nadia will audit (who may do what, what was decided, by whom) is already right there. Port four Planner screens into v1 (Gantt override, five whys, Eval with guardrails, ontology), then build the two missing pieces the goal needs: Stéphane's what-if form and Kevin's night view.

Rules for whoever builds it

Six engineering rules

Never edit the platformExtend through the orchestrator and new operations; write what is wrong in PLATFORM_ISSUES.md.
Guard first, audit lastEvery new operation checks a grant and writes an audit line; the audit is also where "% published" and answer time are computed.
No model in sequencingThe model reads text and writes explanations; the solvers decide the plan.
A test per operationPlus an eval set for the event reader with real messages and injection attempts, rerun at every prompt change.
Host it at Polymex, not on VercelVercel serves our pages and a static demo. The real app needs its Node server, an EU endpoint, a runbook and Nadia's kill switch.
Measure decisions, not loginsPlans published from the app, overrides with a reason, events confirmed in the app, what-ifs answered.
